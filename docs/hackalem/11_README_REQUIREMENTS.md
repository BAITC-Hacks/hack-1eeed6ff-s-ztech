# Полный README: требования, содержание и проверка

**Это один из главных результатов проекта.** Пользователь потребовал максимально подробные инструкции. По п. 5.4.15–16 и 5.6.3–6 положения эксперт должен самостоятельно запустить решение; незапускаемый проект не допускается, поздние пояснения и исправления не принимаются. В технической рубрике Finance README/воспроизводимость — 25 баллов. Документация не должна маскировать незавершённый код.

Мейрам владеет итоговым README; Алишер проверяет его на новом clone и дополняет точные действия UI. Оба подписываются под фактически проверенными разделами в docs/validation.md. Большой объём текста сам по себе не даёт воспроизводимости: каждая команда должна работать с текущего commit.

## 2. Установка и запуск: как оформлять

README должен разделить: «получение исходников», «установка зависимостей», «обычный запуск», «пересборка интерфейса», «проверка». Однократные install-команды не обязаны быть одной shell-строкой. **Сам raw→CSV pipeline запускается одной командой**, без ручного редактирования файлов и ручной загрузки готовых ответов.

Целевой блок после фактической реализации:

```bash
git clone https://github.com/BAITC-Hacks/hack-1eeed6ff-s-ztech.git
cd hack-1eeed6ff-s-ztech
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip check
python run.py
```

Его нельзя выдавать за проверенный до появления requirements.lock/run.py/web/dist. Указать Windows-вариант без обязательной активации и подтвердить его, если заявлена поддержка. В приватный repo эксперт попадает через доступ организатора; это не означает необходимость личного аккаунта участника для работы приложения.

Параметры перечислить точно: `--data data`, `--out results`, `--host 127.0.0.1`, `--port 8000`, `--pipeline-only`, `--verify-only`. Писать только реализованные flags. Опциональный LLM не добавлять в README, если его нет в коде. Ненужные API-key поля в `.env.example` не создавать. Если переменных окружения нет, прямо сказать: «Для основного сценария переменные окружения и API-ключи не требуются».

## 3. Сценарий самостоятельной проверки

1. Эксперт запускает команду и видит успешную проверку raw, размеры графа и время расчёта.
2. Открывает локальный URL, видит настоящие метаданные и run_id.
3. Выбирает любую строку очереди, сверяет gid/роль/score с nodes_roles.csv.
4. Открывает фактические переводы и сверяет суммы, не складывая только одну страницу.
5. Находит произвольный gid из исходных nodes.parquet. Никаких фиксированных идентификаторов для обхода проверки.
6. Находит boundary по фильтру, видит ограничение и отсутствие автоматического terminal.
7. Находит изолированный seed, получает непустую карточку с нулём связей.
8. Открывает кластер, проверяет статистику и гипотезу.
9. Скачивает три CSV, проверяет schemas/rows; запускает verify-only.
10. После установки отключает сеть и повторяет основные действия.

Для удобства демо можно дать 2–3 фактически рассчитанных примера gid, но рядом должен оставаться универсальный сценарий поиска. Примеры не подменяют алгоритм.

## 4. Troubleshooting, которое должно быть фактическим

| Симптом | Что должно быть объяснено |
|---|---|
| Нет Python/не та версия | Как проверить версию и выбрать поддерживаемый interpreter |
| ModuleNotFoundError scipy/pyarrow | Активное окружение, установка из lock, pip check |
| Невалидный parquet/не сходятся агрегаты | Точный файл, ошибка, повторное получение оригинала и hash; без молчаливого ремонта |
| Нет web/dist | Проверенная команда npm ci/build из web, либо получение полного релизного commit |
| Port 8000 занят | `--port 8001` и правильный URL |
| Node/Vite несовместимы | Поддерживаемая версия Node и lock, без советов «обновите всё» |
| Gid округлился в Excel | Импортировать колонку текстом; CSV сохраняет исходную точность |
| Пустой фильтр/не найден gid | Сбросить фильтры, проверить полный gid и выбранный набор |
| Нет сети | Различие установки и runtime; готовые зависимости нужны до отключения |

Не писать workaround, который не проверен. Не скрывать ошибку через `except: pass`, подмену файла или включение fixture.

## 5. Архитектура на миллион узлов — честный раздел

На текущем объёме pandas/NetworkX достаточно как проектное решение. Для миллиона узлов: читать parquet колонками/порциями, хранить adjacency в компактных массивах/графовом движке, пересмотреть центральности и partitioning, вычислять дорогие признаки офлайн, предрассчитывать соседства/агрегаты, давать UI серверные срезы с уровнем детализации. Не держать весь миллион подписанных элементов в браузере. Составить профиль памяти/времени до выбора distributed-системы. Эти изменения — дальнейшая архитектура, не реализованная производительность MVP.
