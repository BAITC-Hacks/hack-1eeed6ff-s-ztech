# Проверка пакета проектирования

23.09.2026. Предмет проверки — документы, исходные материалы и согласованность проектных решений. Это не приёмка ещё не реализованного приложения.

## Выполнено

- Проверены локальные Markdown-ссылки авторских документов: отсутствующих целевых файлов не найдено.
- Проверены парные code fences, отсутствие незаполненных служебных маркеров и корректность JSON evidence/manifest.
- SHA-256 всех 13 файлов исходников/справочного материала/evidence сверены с manifest; hashes исходных parquet совпадают с аудитом.
- SHA-256 двух исходных ZIP-архивов отдельно сверены с записью источников.
- 12 ключевых пунктов пользовательского Master Context сопоставлены с ранее полученным официальным положением после нормализации форматирования: 5.3.1, 5.4.4.2, 5.4.5, 5.4.8, 5.4.9, 5.4.11–16, 5.6.6. Тексты совпали. Стратегические советы и вложенные промпты не приняты за дополнительные официальные требования.
- Пройдена содержательная проверка: схема шести ролей, CSV, строковые gid, целые денежные единицы, дубликаты tx, изоляты, boundary, временная точность, отсутствие ground truth.
- Уточнён порядок алгоритмов: membership предшествует participation; статистика top_gids строится после priority. Циклической зависимости в плане нет.
- Разделены функциональный G3 и независимый чистый запуск G5, чтобы не объявлять финальную воспроизводимость до её проверки.
- Прямые требования пользователя отражены в личных ТЗ, общих документах, AGENTS/CLAUDE и промптах: Мейрам/A, Алишер/B; строгий визуал без градиентов; положение и README — главные приоритеты.
- Не создавались роли готового продукта, application backend или frontend. Оригинальный starter сохранён с раскрытым происхождением.

## Что не подтверждается этим review

Качество классификации на реальной задаче, корректность будущего кода, скорость полного pipeline, работа UI, clean install, прохождение конкурсных требований или факт подачи. Для этого предусмотрены тесты и реальные гейты разработки. Математические правила — предложенная прозрачная эвристика, а не валидированная модель.

## Ограничения источников

Снимки официальных документов сохранены без косметических правок; в исходном Google Docs export есть пробельные строки, в извлечении положения — технические разделители. Это не ошибки авторских документов и не повод изменять первоисточник. Новые объявления организатора после снимка нужно проверить отдельно.
