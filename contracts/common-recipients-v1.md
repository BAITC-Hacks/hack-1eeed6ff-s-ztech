# Общие прямые получатели — аддитивный контракт v1

`GET /api/v1/analysis/common-recipients?gid=A&gid=B&min_sources=2&limit=10`

Endpoint работает в обычном offline-режиме, без OpenAI/ключа. От 2 до 5 разных существующих gid передаются отдельными query-параметрами `gid`. gid — точные строки положительного int64, не Number. `min_sources` по умолчанию равно числу выбранных отправителей; явный параметр допускает порог 2…N. `limit` — 1…10, по умолчанию 10.

Ответ содержит текущий `run_id`, точный отсортированный `source_gids`, `min_sources`, `matched_recipients` до ограничения выдачи, `shown_recipients`, `truncated`, `items`, `limitations`.

Каждый элемент `items`: строковый `gid` получателя, `source_count`, строковая сумма `sum_kzt` с двумя десятичными знаками, `n_tx`, массив `sources`. Каждый source содержит строковый `gid`, `sum_kzt`, `n_tx` и **все** `source_refs` относящихся к паре исходных строк.

Расчёт просматривает все исходные переводы, выбирает только направления выбранный отправитель → прямой получатель, группирует по разным отправителям. Суммы вычисляются целыми тиынами; одинаковые исходные операции сохраняются отдельными строками. Сортировка: число отправителей по убыванию, сумма по убыванию, точный числовой gid по возрастанию. Лимит применяется после подсчёта суммы и количества совпадений. Роли, snapshot и три обязательных CSV не изменяются.

В UI: AI Аналитик → «Общие получатели · без API-ключа». Можно вставить 2–5 gid или последовательно добавлять выбранные на графе узлы. Группа сохраняется при закрытии панели, пока открыта текущая страница. UI ищет получателей **от всех** указанных счетов и показывает вклад каждого и идентификаторы исходных строк; нет совпадений — явный пустой результат. «Подготовить вопрос AI» заполняет текст; оплачиваемый запрос запускается только кнопкой «Задать вопрос».

Инструмент агента `find_common_recipients` принимает `{gids: string[], min_sources: integer, limit: integer}`. В агенте поддерживается только полный охват: набор должен совпадать с полным набором распознанных gid вопроса, `min_sources=N`. Частичный порог оставлен прямому API, чтобы модель не могла молча ослабить условие. Сервер обязательно включает в ответ состав группы, каждый показанный результат и границы интерпретации. Модель выбирает дополнительные основания/следующие шаги из проверенного ledger. Выбор инструмента и понимание формулировки остаются задачей модели; произвольная семантическая полнота не гарантируется. Явная группа из 2–5 gid имеет приоритет перед открытой карточкой другого узла.

Ошибки имеют стандартную оболочку `{error:{code,message,details},run_id}`: 422 для некорректных gid/дубликатов/диапазонов, 404 для неизвестного узла; 403 для нелокального Host. Смена `run_id` очищает рабочее место, поздний ответ после изменения группы не показывается.

Границы: **один направленный шаг**, без трассировки происхождения денег/маршрутов. Сумма — оборот операций только выбранной группы, не весь вход получателя и не уникальные деньги. Неполные входящие, порог выгрузки и граница четырёх колен остаются ограничениями. Общий получатель не доказывает координацию/виновность.
